# APM • Property Marketing Studio

Open **index.html** directly in a current browser. All scripts, images, and icons are local. There is no build, account, or server requirement. The comparison gallery includes this design as concept 10.

## Three paths to try

1. **Agent checkout.** The featured 1301 NE Loop 820 event has 50 postcards going by First Class Mail and 49 brochures shipping to the saved address. Choose **Resume event → Review cart**, accept the terms, and choose **Complete Checkout**. To start at the destination of a marketing email, open `index.html?event=1`.
2. **Approval.** Open **Demo controls**, select **Approval required**, and submit an event's cart. The event list shows the confirmation and status. Open **Categories → Approvals dashboard**, then **Review cart** on that property. Change payment, save and return, or approve. The supplied 4901 N Beach St submission is available immediately.
3. **Detailed customization.** Open any event and choose **Customize** or **Add & customize**. For a postcard, try changing the audience, enabling Informed Delivery, switching sides, editing the artwork, and reviewing the scan. An edit opened from checkout returns directly to the cart.

## Organization and design decisions

- **Listing events** is an inbox with one prominent resume action. The feature pairs a listing photograph with the actual destinations and running subtotal. Status, cart contents, dates, and agent names remain available in the rows. Search and status/type filters combine.
- **Event workspace** puts every eligible product, its configuration summary, and its price on one screen. Editing is optional. Product tabs provide direct access without repeatedly clicking through six products.
- **Product workspace** places the proof beside its options. Mailing fields open immediately. The order summary repeats outstanding requirements near the completion action. Artwork, mailing lists, and checkout forms use a single reusable dialog, replacing its contents when a decision requires another step.
- **Checkout** shows products and fulfillment followed by payment. Its desktop summary stays alongside the form. A compact mobile summary links directly to terms and checkout. The user can return to a specific product and back.
- **Confirmation** provides files and the next available event. Starting another order for the same listing keeps the previous order number and copies its selections into a fresh cart.
- **Demo controls** is available across screens. Use it to switch roles, hide prices, show internal tools, disconnect social accounts, or reproduce uncommon states. State survives navigation and refresh in the same tab when session storage is available. Filesystem browsers that restrict storage can still complete a flow in memory.

## Sample assumptions and limits

- The five-cent discrepancy in the prompt is resolved in favor of the supplied **$206.05** subtotal. Fifty First Class pieces cost **$61.45**, the PDF costs **$2.50**, and the postcard cart line is **$63.95**. Forty-nine brochures cost **$142.10**. The summary shows a separate illustrative 8.25% sales tax. Ground shipping is included.
- The first event is a resumed order with postcards and brochures, plus the two free tools. Fresh eligible campaigns start with postcards, Social Media, Image Download, and Facebook Ad. Prices, copay policy, tax, service windows, additional addresses, and ZIP codes are illustrative.
- Open House dates are relative to the browser's local day so past-date and delivery warnings remain testable. Demo ad minimum is three days. Address validation checks structure, and radius creation saves an audience definition and recipient count. It does not geocode or retrieve household records.
- Two bundled property photographs stand in for the sample listings and template galleries. The editor and downloadable artwork are representations of the third-party design. JPGs and PDFs are generated locally. The preview, production and proof downloads are demonstration files.
- Posting, ad permissions, payment, chat, email, artwork scans, and authentication use local simulations. The main storefront and settings are stubs. Support email and destination links use example.com because the brief provides no production URLs or email.
- The UI requests Lato when installed and uses the specified Helvetica/Arial fallback. Font Awesome glyphs and property images come from assets already present in this repository.
